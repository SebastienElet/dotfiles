# Portage de la politique upgrade

**Objectif :** traiter #198 en conservant `tooling/upgrade`, avec des résultats explicites et
un échec agrégé ; corriger ADR-004 conformément à l’arbitrage utilisateur du 10 septembre.

**Architecture :** wrapper Bash linéaire, orchestration Bun/TypeScript, exécution et compte rendu
communs, politique Git et publication du pin Node séparées. Réutiliser les commandes centrales
de résolution de branche et de validation Node ; conserver la toolchain racine.

**Spécification :** [issue #198](https://github.com/SebastienElet/dotfiles/issues/198), complétée
par l’autorisation explicite de corriger ADR-004 et conserver Moon directement.

Les outils npm, Claude, Codex et Neovim sont optionnels ; Moon et Volta absents contribuent
déjà à l’échec. Brew et mas absents continueront les domaines suivants avec une ignorance
explicite. Les sorties enfants restent visibles. Aucun rollback global n’existe ; les effets
partiels d’une commande externe ne sont pas déductibles de son seul code de retour.

La protection Git couvre pull et commit, avec relecture de branche avant chaque mutation.
Elle utilise le mode local central, heuristique selon ADR-021, sans prétendre résoudre le HEAD
d’un fournisseur. Les défauts de sonde doivent refuser la mutation et contribuer à l’échec.
La synchronisation Neovim reste indépendante de la branche ; un sync échoué ne doit pas
entraîner le commit de son lockfile partiel.

## Étapes et oracles

1. Reproduire les échecs masqués par le point d’entrée Shell dans HOME/PATH temporaires :
   vrais dépôts Git locaux, autres exécutables substitués par un programme TypeScript.
2. Porter la politique : résultat par opération (`succeeded`, `failed`, `not-attempted`,
   `unsupported`), code global 1 si une opération échoue ; dépendances explicites pour
   pull/déploiement, pin/validation/installation/publication et sync/commit.
3. Exercer absence d’outils, JSON invalide/vide, échec de sondes, branches secondaire/détachée,
   commit ciblé sans push, poursuite des plugins indépendants et rejeu après effets partiels.
4. Retirer Shell et son ancien test après comparaison avec ces oracles ; adapter le consommateur
   Node, la tâche Moon et corriger ADR-004. Bun absent devient une erreur de bootstrap globale.
5. Indexer les nouveaux fichiers avant les contrôles ; format, lint, TypeScript 7, suites Bun,
   syntaxe/ShellCheck du wrapper, graphe Moon. Publier PR et preuves/limites dans l’issue.

## Contrats externes consultés

- [npm update](https://docs.npmjs.com/cli/v11/commands/npm-update/) : `before` et
  `min-release-age-exclude` ; les dépendances de Codex restent soumises à la quarantaine.
- [Volta pin](https://docs.volta.sh/reference/pin) : écrit le manifeste du projet courant.
- [Moon upgrade](https://moonrepo.dev/docs/commands/upgrade) : installation `~/.moon` uniquement.
- [Claude plugins](https://code.claude.com/docs/en/plugins-reference) : list JSON, update par ID.
- [Homebrew](https://docs.brew.sh/Manpage), [mas](https://github.com/mas-cli/mas),
  [Lazy](https://lazy.folke.io/usage) : conserver leurs opérations publiques.
- Aide locale Codex 0.153.4 : `plugin marketplace upgrade` rafraîchit les snapshots Git
  configurés ; aucune opération supplémentaire pour les sources locales/gérées par l’hôte.
- Aide locale Claude 2.1.236 et Brew : signatures des commandes de plugins et `upgrade --yes`.

Ces lectures et les fournisseurs substitués ne constituent pas une preuve de mise à jour réelle.
Le rejeu des effets possédés est vérifié avec Git et le manifeste en fixture ; aucune promesse
d’idempotence des téléchargements/installations des fournisseurs n’est ajoutée.

## Résultats locaux du 10 septembre 2026

Environnement : macOS 26.6.2 arm64, Bun 1.4.0, TypeScript 7.0.2, Neovim 0.12.5.
Les fixtures possèdent HOME, PATH, dépôts et remotes Git temporaires ; aucun updater du poste
n’est exécuté. Les intégrations natives sont exécutées hors sandbox système, qui perturbe
les sondes temporaires du shim Git Apple ; leur isolation HOME/PATH reste en place.

- Avant portage : suite Shell et sept tests Node verts ; quinze nouvelles régressions
  constatent un retour 0 malgré un échec injecté, puis passent après portage.
- `moon run tooling:upgrade-test` : 64 tests verts, 280 assertions.
- Tests centraux de branche et de contrat Node : 43 tests verts.
- Neovim/Lazy natifs : l’ancienne commande retourne 0 après un build de plugin échoué ;
  le point d’entrée corrigé refuse le commit. Cette reproduction a précédé la correction ;
  la suite livrée vérifie le résultat corrigé, sans exiger que le défaut externe persiste.
- L’intégration native couvre succès/échec, helper absent/invalide, sondes indisponibles,
  résultats de sondes invalides, tâches encore actives et initialisation Lazy absente.
  Lazy provient du commit canonique de `lazy-lock.json`, les plugins de dépôts Git locaux.
  Le téléchargement de cette dépendance de test dans un répertoire temporaire est aussi exercé.
- Format et lint TypeScript du dépôt, `tsc --noEmit`, syntaxe Bash, ShellCheck, Actionlint,
  Prettier des fichiers touchés et StyLua du helper passent ; luacheck absent localement,
  couvert par la gate Lua existante en CI.

Fournisseurs réellement exercés : Git local et Neovim/Lazy avec sources `file://`.
Brew, mas, Moon, Volta, npm, Claude et Codex sont substitués ; aucun rafraîchissement
authentifié de marketplace ni mise à jour du poste n’est revendiqué. La suite complète
TypeScript, les contrôles Linux et le smoke minimal restent à vérifier dans la CI de la PR.

Un commentaire ajouté : `home/.config/nvim/upgrade.lua` nomme le comportement de Lazy
et l’API des tâches au commit `85c7ff3`, nécessaires pour traduire ses erreurs en sortie non nulle.
