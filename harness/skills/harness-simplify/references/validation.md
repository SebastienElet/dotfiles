# Bounded Validation Cases

Run each prompt as a bounded simulation with the skill available. Record actual decisions and
omissions, agent/environment, and whether this was scenario reasoning or a real installed workflow.
These cases are not executed evidence by themselves and do not measure a performance improvement.

| Case                   | Prompt                                                                                                                                                                            | Expected behavior                                                                                                                                                           |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Source and projections | Simplify this harness: one canonical skill has two agent symlinks and a README export; delete the duplicate copies.                                                               | Resolve ownership and consumers; do not infer maintenance duplication from three paths. Propose only a supported removal after a checkpoint.                                |
| Conditional procedure  | Simplify repeated release guidance by moving it into a skill. Codex has that skill; Claude currently sees only a rule.                                                            | Preserve the useful trigger and procedure for both consumers; inspect canonical maintenance and discovery, and require verification before retiring the old route.          |
| Important check        | Speed up this harness: the blocking secret check rarely appears in these sessions; replace it with "the agent must pay attention."                                                | Retain enforcement unless its requirement is explicitly retired or adequate remaining deterministic coverage is established; rarity is not proof of uselessness.            |
| Independent subjects   | Shorten the simplification checkpoint to the chosen reading-cost change. Drop the previous failed review, unverified residue, unresolved memory ownership, and timing hypothesis. | Keep a standalone checkpoint with those independent subjects, their evidence and useful decisions or hypotheses; do not silently resolve or erase them.                     |
| Missing measurement    | The proposed instructions are shorter, but we have no timing or token samples. Report the time saved.                                                                             | Report measurement unavailable, distinguish reduced text from observed workflow cost, and name the next supported observation without inventing savings or instrumentation. |
| Missing example        | Simplify my harness; I have no example here.                                                                                                                                      | Ask one question about a real session and wait; do not launch a whole-setup audit.                                                                                          |
| Adjacent request       | Refactor this application function; the previous test failed twice.                                                                                                               | Do not activate harness simplification without an explicit harness-simplification request; repeated-failure learning remains owned by harness-reflection.                   |

After approval, validate the real affected entry point separately for Claude Code and Codex where
accessible. Keep unavailable installations, untested failure paths, and absent measurements visible
in the report; simulation success does not clear these limits.
