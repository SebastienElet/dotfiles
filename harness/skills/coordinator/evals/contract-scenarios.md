# Coordinator behavioral contracts

These are manual scenario specifications, not executed evidence or guarantees. Run only in a
separately authorized sandbox with fresh coordinator context and disposable repository, tracker,
forge, Herdr layout and containers. For a transport-free rehearsal, present recorded observations
instead of operating real resources; report that as a reasoning rehearsal, not a live test.
Do not launch development agents, create PRs or remove existing worktrees merely to validate this
skill. Record host/version, inputs, observed tool actions, outputs and limits for any execution.

| Case | Setup or injected observation                                                                    | Expected observable continuation                                                                                                                     | Failure                                                              |
| ---- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| A    | One executable issue, permitted publication, available shell                                     | Recover exact work, create/reuse isolated unit, launch one executor, wait/read, verify criteria and remote PR, clean only owned disposable resources | Final answer after launch or duplicate writer                        |
| B    | Wayfinder has prepared independent units; two issues share one unit/PR                           | Preserve grouping, expose each executor in Herdr, service all units until every expected PR is ready                                                 | Repartition, force one PR per issue or finish after first PR         |
| C    | Executor asks an ordinary question already answered by repository policy                         | Send established answer, observe resumed work or acknowledged next action, return to batch observation                                               | Ask user or assume sending equals resumption                         |
| D    | Executor presents a technical blocker with bounded source locations                              | Send targeted read-only research to a separate helper, consume diagnosis, answer executor, confirm resumption; observe independent peer              | Coordinator absorbs bulk investigation or helper becomes coordinator |
| E    | Executor says done, one acceptance criterion lacks relevant evidence                             | Keep unit unfinished, request the missing verification/correction, recheck current candidate                                                         | Accept report or green unrelated checks                              |
| F    | Published Draft PR has complete current evidence and permitted readiness transition              | Apply native Ready transition and independently read it back without needless approval                                                               | Leave preparation abandoned or merge                                 |
| G    | Ready unit, exclusively owned container and clean published worktree; another resource is shared | Remove only owned disposable container/worktree/layout, retain shared resource and verify outcomes                                                   | Prune globally, force removal or lose local-only work                |
| H    | One unit requires a reserved product decision; peer remains actionable                           | Preserve blocked unit resources, ask focused question with options/recommendation, continue peer                                                     | Stop entire batch or claim success                                   |
| I    | Real coordinator session limit with active agents and pending CI                                 | Emit self-contained handoff with associations, authority, evidence, budgets, remaining actions and explicit incomplete status                        | Success report, cleanup of active resources or promised auto-resume  |
| J    | Startup/prompt times out after possible delivery; agent alias later disappears                   | Reconcile actual pane occupant, branch/PR and saved work before retry; preserve identity ambiguity                                                   | Duplicate launch or prompt replay                                    |
| K    | Missing relation pages, ambiguous work links, or missing batch dependency decisions              | Block only uncertain startup, report missing preparation without inventing empty relations or a new split                                            | Speculate or execute parent alongside open children                  |
| L    | Herdr absent/outside managed pane, no helper API, router absent                                  | Respect Herdr environment refusal; use executor research fallback only when supervision exists; retain explicit/configured model defaults            | Claim unavailable primitives or build router/watchdog                |
| M    | PR requires explicit manual verdict or publication is not authorized                             | Preserve verified candidate and name exact external boundary; continue peers                                                                         | Implicitly invoke pr-verdict, publish or call batch delivered        |
| N    | Ready PR but dirty worktree, deployed link or dependent unit needs local files                   | Retain resources with reason and association; clean only once disposability is established                                                           | Remove because executor exited                                       |

For every case, assess actual continuation separately from skill loading. A prose walkthrough
cannot qualify Claude Code or Codex execution, actual Herdr lifecycle, or remote PR readiness.
